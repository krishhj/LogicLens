Technical Scaling

O(1)

Constant time operations independent of input size.

Math Calculation: Regardless of the input size N, the algorithm executes the exact same number of operations. Evaluating an array index like arr[5] fundamentally calculates Base_Address + (5 * Element_Size) executing in exactly 1 hardware clock cycle.

O(log n)

Logarithmic algorithms like binary search.

Math Calculation: The problem space is aggressively quartered/halved per loop cycle. If N = 100, halving it drops to 50, then 25, then 12... meaning it takes roughly log₂(100) ≈ 7 operations instead of 100 loops. This makes sorting scaling practically flat.

O(n)

Linear complexity processing each element.

Math Calculation: The algorithm strictly executes one operation sequentially per element. So for iterating across an Array constraint of length N, the logic engine must loop exactly N times. E.g. finding the Maximum number via naive linear checks.

O(n log n)

Efficient sorting algorithms like Merge Sort.

Math Calculation: A hybrid structure: the algorithm iterates structurally parsing exactly N items sequentially during compilation blocks, but recursively halves the physical tree mappings exactly log₂(n) times, resulting algorithmically in N * log₂(N) execution jumps natively.

O(n²)

Nested loop algorithms like Bubble Sort.

Math Calculation: When evaluating arrays, deploying double-loops inherently forces you to multiply lengths. A loop checking N elements, wrapping another internal nested loop scanning N elements explicitly triggers mathematically N * N = N² operations natively.
